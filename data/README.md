# Reference examples database

`reference_examples.json` is the canonical source for bundled screening presets.
The CSV and packaged JSON are generated by `scripts/sync_reference_data.py`.

Use the records with the CLI:

```bash
quantity-quality lookup heat-80c-standard
quantity-quality annotate examples/adoption_records.csv --output runtime/annotated.csv
```

## Files

- `reference_examples.json` — canonical data source.
- `reference_examples.csv` — generated spreadsheet export.
- `quantity_quality_record.schema.json` — input/output JSON Schema.
- `stream_calculation_request.schema.json` — unified Python/CLI/HTTP/agent request Schema.
- `energy_accounting_request.schema.json` — primary-secondary-final-useful-Applied Exergy request Schema.

## Scope and limitations

These records are examples, not a universal property table:

- electrical and mechanical factors are reporting conventions at the declared
  work-delivery boundary;
- thermal and cooling values are reproducible calculations from the temperatures
  and equations stored in each record;
- solar and generic blackbody radiation use the declared Petela model and
  reference temperature;
- biomass, waste, biogas, and other heterogeneous bioenergy carriers have no
  universal factor: supply matching-basis measurements or component properties;
- methane and hydrogen values are rounded reference defaults; and
- petroleum and coal values marked `illustrative_reference` are approximate web
  presets and should be replaced with composition-, grade-, and source-specific
  data for engineering, contractual, or regulatory work.

Every new record should identify a stable source, basis, boundary, calculation,
and confidence class. Prefer a DOI, standard/table identifier, or versioned public
URL in `source`. If no independent source is available, label the value as an
illustrative convention rather than presenting it as a measured property.

The canonical paper explains the equations and limitations. Corrections with
reproducible working and stable citations are especially welcome.
The [numerical validation guide](../docs/validation.md) records authoritative
unit/property sources, pinned public-data snapshots, tolerances, and the full
real-data validation command.
The [physical-stream guide](../docs/physical-streams.md) documents mechanical,
electrical, fluid, humid-air, biomass, radiation, separation, nuclear, friction,
and aerodynamic-drag calculations. The [fields, plasma, and nuclear
guide](../docs/nuclear-plasma-electromagnetic.md) defines the advanced
electromagnetic, reaction-product, plasma-state, and radiation-entropy paths.
Those models use measured request inputs and are not a table of fixed factors.

## Field dictionary

- `id` — stable machine-readable identifier.
- `name` — human-readable example name.
- `category` — thermal, chemical, electrical, storage, measurement, or another broad class.
- `carrier` — carrier or stream type.
- `basis` and `basis_type` — calculation convention and machine-readable class.
- `quantity_unit` — carrier-aware example unit.
- `exergy_factor` and `factor_unit` — accessible exergy per unit reported energy.
- `reference` — declared sink, energy basis, or reference convention.
- `boundary` — boundary where the factor applies.
- `calculation` — concise reproducible calculation note.
- `adoption_note` — intended screening use and important caveats.
- `source` — provenance of the value.
- `source_c`, `sink_c`, `cold_service_c`, and `ambient_sink_c` — explicit temperatures when relevant.
- `return_c` — return temperature for an integrated sensible-heat stream; it is distinct from `sink_c`, the reference environment.
- `fuel_basis` — HHV or LHV denominator when relevant.
- `confidence` — `framework_convention`, `computed_reference`, `reference_default`, or `illustrative_reference`.

Operational records can use `reference_id` to copy a bundled example's factor,
reference, boundary, basis, and temperature context into annotated output.
Records created through `calculate_stream()` also carry `stream_type`,
`quantity_method_id`, `method_id`, and `calculation_inputs`, so both the energy
quantity and its Exergy Factor can be reproduced.
Every serialized stream also includes a `distinguishability` object that states
the source/reference difference already represented by `fx`; it is evidence, not
another multiplier. End-use accounts keep energy stages in standard energy units,
Applied Exergy in `_ex` units, and societal services in non-energy outcome units.
Energy-only stages may omit `fx`; `accounting_method` preserves physical-content,
total-energy-supply, direct, or substitution conventions without treating a
counterfactual substitution value as physical exergy.

## Contribution standard

New records must declare the reporting boundary, reference environment, carrier,
energy basis, formula or table, confidence class, and a stable source. Include a
regression test for every added or corrected number.
